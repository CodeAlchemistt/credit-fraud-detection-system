System Overview

How It Works

Step 01

Data Ingestion

Transaction data enters the pipeline. PCA-reduced features (V1–V28), transaction amount, and time are extracted from the Kaggle dataset and stored in MySQL.

Step 02

ML Inference

Features are scaled with RobustScaler and fed to a trained classifier. SMOTE oversampling addresses the 0.17 % class imbalance during training.

Step 03

Real-Time Decision

The model returns a fraud probability score. Transactions above the threshold are flagged as BLOCKED; clean ones as APPROVED.

01 The Kaggle Dataset

V1–V28 (PCA) + Time + Amount

The dataset is sourced from the ULB Machine Learning Group on Kaggle . Due to confidentiality, the original features have been transformed via Principal Component Analysis (PCA), resulting in components V1 through V28. Only Time (seconds since first transaction) and Amount are untransformed.

The dataset spans two days of transactions and presents one of the most cited examples of extreme class imbalance in applied machine learning — a challenge that required careful handling during model training.

02 Class Imbalance Challenge

Class Distribution

Why This Matters

A naive classifier that labels every transaction as legitimate would achieve 99.83 % accuracy — yet detect zero fraud. Accuracy alone is therefore a misleading metric.

To counteract this, SMOTE (Synthetic Minority Over-sampling Technique) was applied to the training set, generating synthetic minority-class examples so the model learns discriminative boundaries for both classes equally.

Evaluation focused on Precision, Recall, F1, and AUC-ROC rather than raw accuracy.

The Amount feature was normalised using RobustScaler (median + IQR), making it robust to the heavy-tailed distribution visible in the chart above. The Time feature was converted to "hour of day" to capture cyclical spending patterns. All 28 PCA components were used without further dimensionality reduction.
